# VM 执行器输出验证协议（agentB 提供）

## 目的
VM 执行器输入 cap 后输出 base，与 36 样本验证集对比，确认模拟正确性。

## 数据资产
- **验证集**: `wb-pmos-nx/tmp_b_files/nx_vm_verify_dataset.json`（36 样本，统一格式）
  - `{nsd, src, cd, cap, base, keys2, block, pair22, env68, env73}`
  - 8 实时样本含完整 `cd/cap/base/keys2`（最可靠，**优先用这批验证**）
  - 12 A236 样本无 cd/cap（仅 base+env，用于同环境变体观察）
- **IO 对**: `wb-pmos-nx/tmp_b_files/nx_io_pairs.json`（16 样本 cap+base）
- **采集脚本**: `wb-pmos-nx/728_B_capture_all.js`（可采集新的 cd/cap/base/keys2）

## 验证流程（三阶段）

### 阶段 0：环境确认
- VM 执行器输入 = `cap`（113 开头完整数组，即 b86[2:] 解码后的明文 basearr）
- 对 8 实时样本：`cap = b86[2:]`（b86 = decodeB86(cd)，NX_BS 64 字符映射）
- 可选输入：`366669` 参数（nx_ax_input.json 中的第二个值，含义待确认，先按固定值传入）

### 阶段 1：base 结构匹配（硬校验，必须全过）
对每个验证样本，执行器输出 base 必须满足：

| 字段 | 位置 | 校验规则 |
|---|---|---|
| 固定头 | [0:22] | = `179,0,127,12,181,215,238,205,190,124,137,242,104,101,0,202,211,238,166,172,241,181` |
| 固定段 | [29:68] | 与样本 base[29:68] 一致（pairs 内恒定，可直接取样本值） |
| 编码总长度 | — | huffman bits（nxEncrypt68 编码后总 bits）与样本一致 |
| 块核心 | 任意偏移 | 属于 6 模板之一：A/B/A2/C/D/E（见下） |

块核心模板：
- A: `76,0,25,10,171,221,218,233,234`
- B: `49,144,170,189,221,174,158,169`
- A2: `105,171,119,0,221,218,233,234`
- C: `249,117,222,42,169,237,173`
- D: `77,158,17,7,119,143,23,17`
- E: `100,217,225,16,119,121,241,113`

### 阶段 2：cd 绑定字段匹配（核心验证，决定模拟正确性）
**这些字段是业务层/WAF 校验的关键，必须与样本一致：**

| 字段 | 位置 | 说明 |
|---|---|---|
| **env73** | [68:73] | **最关键**。= f(cd) 确定性（同 cd 固定）。执行器输出必须 == 样本的 [68:73]（5 字节） |
| **pair22** | [22:29] | 会话段，与 env73 配对。执行器输出必须 == 样本的 [22:29]（7 字节） |
| env68 | [68:75] | env73 + [73:75]（[73:75] 同 cd 固定，执行器应输出一致值） |
| 块类型 | — | 允许不一致（同 cd 下块类型可自由变化，见阶段 3） |

**匹配判定**：对 8 实时样本，执行器输出的 env73 + pair22 必须与样本逐字节一致（16 字节全部命中 = 模拟正确）。

### 阶段 3：允许差异的字段（验证自由度）
- **块类型**：同 cd 下可变化（800 实验证明任意块类型 + 保持 bits → 200）。执行器输出任一块类型即可（只要总 huffman bits 与样本一致）
- **[75:110] 块区**：可自由（任选块模板 + 保持 bits）
- **[110:137] 变体区**：同 cd 固定，执行器应输出一致（与样本 [110:137] 对比，允许 A236 组的 13/14 变体）
- **[137:] 固定尾**：硬编码 `202,156,93,134,194,236,25,97,68,217,159,0,102,0,143,144,111,222,85,222,13,15,193,124,69,26,121,132,159,68,0,0,0`（尾部对齐）

## 判定标准
- **阶段 1 + 阶段 2 全过**（8 实时样本 env73+pair22 全命中）→ 执行器正确，纯算法达成
- 阶段 1 过但阶段 2 失败 → 执行器有 bug（env73 生成逻辑错误）
- 阶段 1 失败 → 执行器输出结构错误

## 实弹验证（最终确认）
执行器生成 base 后，用 `buildCookie` 流程（参照 `wb-pmos-nx/784_same_len_independent.js` 的 cookie 构建）：
1. nxEncrypt68(base) → XOR keys2(前16) → encryptMode1(keys17) → be
2. na = [4,8,r2mka,start,48,keys2,beLen,be]
3. P cookie → API 请求 → 期望 200
- 对 8 实时样本逐一验证：执行器 base + 对应 cd 的 keys2/keys17 → API 必须 200

## 补充注意
- A236 12 样本（同环境不同 cd）：env73 有 3 种模式（215,229,76,138,222 / 36,200,173,225,157 / 177,208,36,200,173）——用于验证执行器对"同环境不同 cd"的输出差异
- 若执行器输出与样本不符，优先检查 env73 生成逻辑（最可能 bug 点）
- 数据集保持就绪，采集脚本可用，可随时补样本
