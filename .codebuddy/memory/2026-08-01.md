# 2026-08-01 - nx 沙箱死循环定位

## 背景
用户提问：xj 经验中"Node vm 沙箱跑外层 VM"是核心突破，为何 nx 站点没有第一时间用沙箱，而是一直尝试其它方案。

## 诚实复盘（回答用户）
1. 沙箱在 xj 就不是完全成功（密钥在 JSVMP 闭包，纯沙箱无法导出 keys，需配合管线反解）
2. 管线是 xj 的 100% 方案，nx 兄弟站点自然先复用管线（省力路径）
3. 管线失败后走了"浏览器 hook + 结构分析"增量路线（xj 后期成熟方法）
4. **沙箱其实试了（57 脚本）但诊断错误**：当时归因"nx 反检测更强"，放弃——真正根因是 **buildEnv 写死 xj 的 location/UA/domain**，nx 外层 VM 检测 location 不匹配 → 死循环

## 已修复 + 定位成果
- **buildEnv 参数化**（output/keygen/sandbox_keygen.js）：target/ua/domain/port 从 opts 读取，nx 用 target='https://pmos.nx.sgcc.com.cn:10443/' + UA
- **xj 沙箱回归验证**：参数化后 xj 仍正常（cookie 生成成功）
- **nx 动态代码死循环定位**（patchDyn 插桩选项）：
  - nx 动态代码 = **递归式 VM**：`_$ml(_$mB,...)` 7 参数递归 dispatcher，293 个 debugger 语句，数百 trampoline（`_$kE.apply(this,[子程序号,...])`）；xj = 迭代式（`_$lx` 3 参数 if 树）
  - 死循环链：`_$ml` 递归 0→9→6→1144，子程序 1144 的 opcode 522（return 对象）后递归返回处理卡住（wh=38 全局迭代停）
  - 环境补丁无效（TextEncoder/BigInt/SharedArrayBuffer 补充后仍死循环，missing=0）→ VM 逻辑性死循环
- **定位方法论**：inspector.Session + _debugProcess(SIGUSR1) 中断抓堆栈；patchDyn 插桩 `_$ml` 子程序号/opcode/PC/trampoline/递归返回
- **关键 VM 语义**：`_$kK`=opcode，`_$bj`=PC（`_$eO[_$bj++]` 取指令），`_$eO=_$fW[1]`=字节码数组（长度 2553）

## 结论
- nx 沙箱需深度 VM 语义还原（递归 dispatcher 返回处理），工程量大于浏览器辅助方案 → **沙箱路径暂缓**
- 纯算法 keys 两个路径（管线 runTask / 沙箱）都需深度 VM 还原
- 当前可交付：浏览器辅助（wb-pmos-nx/58_browser_assisted.js，构造 cookie 浏览器内 200）
- 详细文档：wb-pmos-nx/BREAKTHROUGH.md §9

## 教训（写进经验）
- **沙箱环境必须参数化站点**（location/UA/domain），复用前先检查写死值
- **沙箱失败先查环境配置**（location 匹配），再归因"反检测更强"
- nx 与 xj 的 VM 结构不同（递归 vs 迭代 dispatcher），跨站复用沙箱需适配 VM 结构差异

## ★ 应用 xj 文档方法到 nx（关键点突破应用，08-01 晚）
用户要求：从 rs-jsvmp-crack.md 学 xj 前期突破方法应用到 nx。结果：

### K2（jsdom 密钥计算器）→ nx 被反制 ❌
- jsdom（Node22 + kimi 仓库）跑 nx 外层 VM **成功生成 P cookie**（len=343，浏览器 535）
- 但 jsdom 捕获的动态代码**变量名被混淆成 `ā`**（304KB，沙箱是正常 `_$xx` 492KB）+ 内层 VM 反复 TypeError（`_$c8[_$fz] is not a function` / `prototype` undefined）
- canvas/webgl/ResizeObserver/IntersectionObserver/Worker/Path2D/DOMMatrix/TextEncoder 补全后仍混淆 → **nx 检测 jsdom 环境生成混淆代码**（比 xj 反检测强）
- **结论：jsdom 密钥计算器对 nx 不可用**（排除）

### 沙箱 vm 逃逸（重要工程发现）⚠️
- **根因**：buildEnv 传宿主 `Function` → 瑞数 `Function("return typeof process")()` 检测到 `process=object` → 走反检测死循环
- **修复**：`delete sandbox.Function` + createContext 后 `vm.runInContext('(function(){}).constructor')` 取 vm 内建 Function（受限）→ `Function('process')=undefined` ✓（注意：不能 `vm.runInContext('Function')`，Proxy get trap 挡原型链）
- **但死循环仍在**（`_$ml(1144)` opcode 522 return 后、子程序 6 处理返回值卡住）→ nx 有更深反检测（候选：Error.stack 格式/navigator 细节/canvas 渲染）
- 死循环定位链（patchDyn 插桩）：`_$ml` 递归 0→9→6→1144，wh=38 全局迭代停，ret812=true（递归返回但调用者不继续）

### 结论
- nx 反检测比 xj 强一个量级：jsdom 混淆反制 + 沙箱多层反检测（递归 VM + 逃逸检测 + 更多）
- 浏览器辅助（58 脚本）仍是唯一可用路径
- 沙箱死循环需继续还原 nx 反检测点（Error.stack 伪装是下一步候选）

## ★★ 发散思维突破尝试（08-01 深夜，8 类反检测排查）
系统性突破 nx 反检测，全部尝试 + 结果：

| # | 尝试 | 结果 |
|---|---|---|
| 1 | Proxy 作全局 → 普通 sandbox 作全局 | ✅ 修复（vm 内建 eval/globalThis 可达——Proxy 挡原型是死循环首因之一） |
| 2 | vm 逃逸封堵（Function → process） | ✅ 修复（`Function('return process')` → undefined；用 `vm.runInContext('(function(){}).constructor')`） |
| 3 | Error.stack 伪装（去 node:vm 帧） | ⚠️ 未生效（replace 需验证），非死循环根因 |
| 4 | eval.toString 伪装 | ❌ 无效（瑞数用 Function.prototype.toString.call(eval)，实例 toString 骗不过） |
| 5 | 原生 eval（vm 内建） | ⚠️ jsdom TypeError 消失，但沙箱死循环不变 |
| 6 | 环境 API 补全（fetch/WebSocket/indexedDB/BroadcastChannel/PerformanceObserver/caches/name） | ✅ missing 从 13 → 4（剩 IE 专属 execScript 等，Chrome 无正常） |
| 7 | jsdom 原生 eval（不 hook） | ✅ **混淆消失**（window 上 `_$` 12 个、`ā` 0）——**jsdom 混淆 = eval 被 hook 导致**！ |
| 8 | **jsdom keys2 严格 uuid 校验** | ❌ **uuidOk=false**——jsdom cookie 用浏览器 keys16 解不开！ |

### ★★★ 重大认知（推翻 xj 假设）
- **nx 的密钥生成依赖环境**：jsdom keys2（a5 72...）≠ 浏览器 keys2（8b cd...），jsdom cookie 用浏览器 keys16 解密 uuidOk=false（无有效匹配）
- **xj 的"密钥 f(nsd,cd) 纯计算、与指纹正交"对 nx 不成立**！nx 的密钥含环境依赖（jsdom/浏览器不同）
- 含义：纯算法 keys（沙箱/jsdom）**无法获得浏览器一致密钥**（jsdom 环境算出的密钥与浏览器不同）

### 发散思维最终结论
- nx 反检测 = 纵深防御：jsdom 混淆（hook 检测）+ 沙箱死循环（VM 逻辑层，环境排除）+ **密钥环境依赖**（非纯计算）
- 8 类环境修复后沙箱死循环位置不变（`_$ml(1144)` opcode 522 return 后，inst=1144，wh=38 停）→ VM 逻辑层卡点
- **纯算法路径（沙箱/jsdom/管线）全部受阻**，浏览器辅助（58）唯一可用
- jsdom 混淆的"eval hook 检测"是通用教训：hook eval 会被瑞数检测（nx），用原生 eval + document.cookie 捕获
