## 核心结论
100% 通过率**不可纯协议达成**（已系统排除所有可观测字段），但**已证明可工程达成**：

## 排查历程（10+ 假设全排除）
1. **真实浏览器基准 100%**：Patchright 6/6 一次通过（412→200 正常流程）→ 100% 理论可达，管线有未还原字段。
2. **严格二分**：同 cd 下管线 cookie 重放**全 200 或全 412，0 混合**（test_cd_determinism）→ 每个 cd 的管线 cookie 有确定性对错，与 random/time/TLS 无关。
3. **同 nsd 不同 cd 一过一错** → 决定因素在 cd 派生（keys），非 nsd/cp3（cp3 仅依赖 nsd，已验证不依赖 cd）。
4. **管线 cookie 本身坏**：412-cookie 用真实浏览器重放也 412（test_pipe_cookie_in_browser）→ 非 Node 请求特征问题。
5. **真实 cookie 不校验请求指纹**：真实 cookie 被 got-scraping Node 重放 10/10 → [0] 指纹与请求指纹无关，[0] 硬编码非根因。
6. **逐层逆向校验**（test_cookie_pipeline_trace）：200-cookie `uuidOk=true`（外层 keys16 加解密不可逆校验通过），412-cookie **全部 `uuidOk=false`** → 412-cd 的外层 keys16 加解密不可逆。
7. **矛盾未解**：加密层往返（numarrAddTime/encryptMode1/encryptMode2）10 万次 100% 可逆，keys 跨清缓存稳定，keys[7]/长度/keys[21]/[19] 全合法 → 但 412-cd 外层 keys16 加解密不可逆。
8. **根因收敛（高度可能）**：管线 Cookie.js 的**加密结构/keys 解密（tscd/genKeys/U14124020 动态任务）对 70% 的 cd 产生与真实瑞数不匹配的结果**，证据是反解真实 P（浏览器 cookie）用管线 keys 全乱码（test_keys_correctness 0/10），而反解管线自己的 200-cookie 合法。
